# 固定資産管理の業務フロー

freee固定資産 Public APIを、複数のAPI操作やWeb画面での操作を組み合わせて安全に使うためのガイド。

一覧取得、詳細取得、登録など、単一のAPI呼び出しで完結する操作方法はこのレシピに重複して書かない。各エンドポイントの必須項目、型、制約、呼び出し例は、正式OpenAPIから自動生成される `references/fixed-asset-management-fixed-assets.md` を参照する。

このレシピで扱うのは次の業務フローに限る。

- PUTによる全項目更新で、既存値を失わずに一部項目を変更する
- 物理削除と除却・売却を区別し、誤った削除を防ぐ
- APIで扱えない異動処理を、対象資産を特定したうえでWeb画面へ引き継ぐ

## 共通の事前確認

1. `freee_server_info` でサーバーバージョンを確認する
2. `freee_get_current_company` で対象事業所と `company_id` を確認する
3. `references/fixed-asset-management-fixed-assets.md` で、使用するメソッドの必須項目・型・制約を確認する

`company_id` は現在の事業所と一致させる。対象事業所を変更する場合は、先に `freee_set_current_company` で切り替える。

## 業務フロー1: 既存値を保持して一部項目を更新する

更新APIはPUTによる全項目更新であり、PATCHのような部分更新ではない。「管理番号だけ変える」などの依頼でも、変更項目だけを送ると既存値を失うおそれがある。

1. `GET /hub/fixed_asset_management/fixed_assets/{id}` で最新の詳細を取得する
2. 正式リファレンスに記載されたread-onlyフィールドを除外する
3. 変更対象だけでなく、更新後も保持するすべての書き込み可能項目をbodyに含める
4. 資産名、管理番号、対象事業所と変更前後の差分をユーザーに示す
5. bodyに `company_id` を加え、ユーザーの依頼内容に照らして確認したうえで `PUT /hub/fixed_asset_management/fixed_assets/{id}` を呼び出す
6. 詳細GETを再実行し、意図した変更と既存値の保持を確認する
7. 更新後のWeb確認URLを案内する

現況値、償却スケジュール、異動履歴、状態フラグ、元資産参照などはread-onlyとなる。GETレスポンス全体をそのままPUTしてはならない。完全な対象フィールドは正式リファレンスで確認する。

資産の状態によって更新できない項目がある。入力エラーが返った場合はフィールド別のエラー情報をユーザーに示し、値を推測して再試行しない。

## 業務フロー2: 物理削除と異動処理を判定する

ユーザーの「消して」「使わなくなった」といった表現だけでは、次のどちらを意図しているか確定できない。

- 登録ミスなどを台帳から完全に消す物理削除
- 使用終了を履歴として残す除却・売却などの異動処理

次の順序で判定する。

1. 詳細GETで対象資産の最新情報を取得する
2. 資産名、管理番号、取得日、取得価額、現在の状態、対象事業所を示す
3. ユーザーの目的が「登録自体を取り消す」か「使用終了を記録する」かを確認する
4. 目的に応じて、後述の物理削除またはWeb画面への引き継ぎへ進む

### 物理削除する場合

DELETEは物理削除であり復元できない。

1. 詳細GETで現在の状態と異動履歴を確認し、登録ミスとして物理削除する対象かを確認する
2. 対象資産と対象事業所を再提示する
3. 物理削除で復元できないことを説明し、ユーザーから明示的な実行確認を得る
4. `DELETE /hub/fixed_asset_management/fixed_assets/{id}` を呼び出す
5. 成功レスポンスを確認してユーザーに報告する

ユーザーの明示的な実行確認なしにDELETEを実行してはならない。「消して」という最初の依頼だけを、復元不可の操作に対する確認として扱わない。
削除できない資産はAPIが400エラーを返す。削除可否を事前に断定せず、エラー時は物理削除を行わずに理由をユーザーへ示す。

### 除却・売却などを行う場合

除却・売却・減損・耐用年数短縮などの異動登録や、資産ステータスの直接変更はAPIでは行えない。

1. APIで異動を再現するPUTやDELETEは行わない
2. 対象資産の詳細GETで、資産名、管理番号、現在の状態、対象事業所を確認する
3. Web画面で操作が必要であることを説明する
4. 次の詳細画面URLを案内し、ユーザーがWeb画面で異動内容を最終確認できるようにする

```text
https://fixed-asset.secure.freee.co.jp/fixed_assets/{id}
```

一覧画面から対象を探す必要がある場合は、次を案内する。

```text
https://fixed-asset.secure.freee.co.jp/fixed_assets
```

URLの `{id}` には詳細GETで取得・確認した固定資産IDを使う。IDを推測しない。Web画面のURL仕様が正式公開時に異なる場合は、正式な画面URLを優先する。

## 結果の伝え方

- 更新時は、対象資産、変更前後の差分、再取得による確認結果、Web確認URLを示す
- 物理削除時は、削除した対象と、復元できない操作が完了したことを示す
- 異動処理時は、APIでは未実行であることと、続きの操作を行うWeb画面URLを明確に分けて示す
- API呼び出しに成功していない場合は、完了したように表現しない

## エラー対応

実行時点の正式OpenAPIを優先する。このレシピとOpenAPIが異なる場合は、OpenAPIに従う。

- 400: フィールド別のエラー情報を確認し、修正が必要な値をユーザーに示す
- 401/403: `freee_auth_status` と現在の事業所を確認する
- 404: 資産IDと対象事業所を確認する
- 409: 最新の詳細を再取得し、競合内容を確認してからユーザーに再実行の判断を求める
- 429: 応答の再試行指示に従い、呼び出し回数を抑える

事業所が誤っている場合は、`freee_list_companies` で候補を確認し、ユーザーの意図に合う事業所へ `freee_set_current_company` で切り替えてから再実行する。
